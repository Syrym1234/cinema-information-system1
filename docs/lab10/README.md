# №10 зертханалық жұмыс - HTTP REST API

**Тақырып:** ақпараттық жүйе компоненттерінің HTTP REST API арқылы өзара әрекеттесуі.
**Пәндік сала:** кинотеатр. **Ресурс:** Movies. **Стек:** Node.js + Express + SQL Server.

Тапсырмадағы кітапхана/MySQL коды - түсіндіруші мысал. Бұл жұмыста сол бес CRUD маршруты бұрынғы кинотеатр жобасының `CinemaSchoolDB` базасына бейімделді. `mysql2` және жаңа кітапхана жобасы қажет емес; SQL Server үшін `mssql` драйвері қолданылады.

## Іске қосу

Node.js 20 немесе одан жаңа нұсқа және SQL Server қажет. Репозиторий түбірінде:

```powershell
npm ci
Copy-Item .env.example .env
```

`.env` ішіне өз SQL Server параметрлеріңізді енгізіңіз. Құпиясөз GitHub-қа жіберілмейді.

**Windows Authentication / SQL Express** үшін, осы компьютерде тексерілген баптау:

```dotenv
DB_AUTH=windows
DB_SERVER=.\SQLEXPRESS
DB_NAME=CinemaSchoolDB
DB_ENCRYPT=false
DB_TRUST_CERT=true
HOST=127.0.0.1
PORT=3000
```

Атаулы instance қолданғанда `DB_PORT` жолын алып тастаңыз. Windows-та optional `msnodesqlv8` пакеті және Microsoft ODBC Driver 17 қажет. Басқа драйвер орнатылса, мысалы `DB_ODBC_DRIVER=ODBC Driver 18 for SQL Server` деп көрсетіңіз. `DB_AUTH=sql` режимінде `.env.example` ішіндегі SQL логин/құпиясөз және TCP порты қолданылады. Linux/macOS-та SQL Authentication пайдаланыңыз.

Таза базаға SSMS арқылы тек `sql/01_create_database.sql`, кейін `sql/02_insert_data.sql` файлдарын бір рет орындаңыз. **Бұрыннан толтырылған базаға бұл файлдарды қайта орындамаңыз.** №10 үшін миграция немесе жаңа кесте қажет емес.

```powershell
npm start
```

Афиша: <http://127.0.0.1:3000/>. Фильмдерді басқару: <http://127.0.0.1:3000/catalog.html>. База тексеруі: <http://127.0.0.1:3000/api/health>. Спецификация: <http://127.0.0.1:3000/api/openapi.json>.

## Postman арқылы көрсету

1. **Import** арқылы `postman/CinemaLab10.postman_collection.json` және `postman/Local.postman_environment.json` импорттаңыз.
2. `Cinema Local` environment таңдаңыз. `baseUrl` серверіңіздің адресіне сәйкес болсын.
3. Серверді іске қосып, коллекцияны **Run collection** арқылы бір рет, бастапқы ретімен орындаңыз.
4. 25 сұраныстың статусы және 94 assertion нәтижесін тексеріңіз.
5. `movieId`, `genreId`, `protectedMovieId` автоматты түрде алынады. Қатты жазылған ID қажет емес. Коллекция өзінің уақытша фильмін соңында жояды; бұрынғы фильмдер өзгертілмейді. Сынақ үзілсе, тек `Lab10 | ...` атаулы өзінің уақытша фильмін каталогтан жоюға болады.

CLI баламасы (Newman - Postman коллекциясын орындайтын бөлек тест құралы):

```powershell
npm test
npm run test:postman
```

CLI командасы Newman 6.2.3 құралын `npx` арқылы бөлек жүктейді. Оның upstream ескірген транзитивті пакеттеріне байланысты ескертулері болуы мүмкін; ол қосымшаның runtime тәуелділігіне кірмейді. Postman desktop Runner осы коллекцияны қосымша npm құралынсыз орындайды. Жоба тәуелділіктерінің аудиті: `npm audit` - 0 осалдық (04.11.2026). Есептің негізгі алты сұранысы ресми Postman Web интерфейсінде Send арқылы, жергілікті Desktop Agent 0.5.2 көмегімен орындалды. Толық 25 сұраныстық автоматты тексеру Newman журналында сақталған.

## API келісімі

| Әдіс | Endpoint | Сәтті жауап | Қате жағдайлар |
|---|---|---|---|
| GET | `/api/movies` | 200, фильмдер массиві | 500/503 |
| GET | `/api/movies/:id` | 200, фильм және жанр | 400, 404, 500/503 |
| POST | `/api/movies` | 201, фильм + Location | 400, 413, 415, 500/503 |
| PUT | `/api/movies/:id` | 200, жаңартылған фильм | 400, 404, 413, 415, 500/503 |
| DELETE | `/api/movies/:id` | 200, message + movie_id | 400, 404, 409, 500/503 |

POST және PUT үшін `Content-Type: application/json`. PUT барлық жеті жазылатын өрісті талап етеді. `movie_id` серверде жасалады. Белгісіз өрістер қабылданбайды. Мысалдағы `genre_id` мәнін `/api/metadata` нәтижесінен таңдаңыз:

```json
{
  "title": "Жаңа көкжиек",
  "genre_id": 1,
  "duration_min": 110,
  "age_rating": 12,
  "release_year": 2026,
  "rating": 8.5,
  "description": "Кинотеатр каталогындағы жаңа оқу фильмі."
}
```

Қате келісімі: `{"error":"Адам оқитын сипаттама","code":"ERROR_CODE"}`; валидацияда қосымша `details` массиві бар. SQL хабарламалары мен құпиясөз клиентке жіберілмейді. Сеанстармен байланысқан фильмді жою 409 қайтарады; CASCADE DELETE қолданылмайды.

## Қайталап тексеру және шекаралар

- 11 автоматты unit test; 25 нақты HTTP сұранысы / 94 Postman assertion; 11 браузер тексеруі өтті.
- Браузерде қосу, өзгерту, жою, FK қатесі, desktop/mobile және бұрынғы каталог/есеп тексерілді. Негізгі есептегі 6 сурет `evidence/postman-web/` ішінде. Postman-да ID=6 фильмі оқылып, ID=39 уақытша фильмі қосылды, жаңартылды және жойылды. SQL SELECT рейтингтің 8.5 → 9.1 өзгеруін және кейін жазбаның жоқтығын растады; каталогта 24 фильм қалды.
- Бұл жергілікті оқу ортасы: аккаунт, рөлдік әкімші құқығы, нақты төлем және TLS бұл жұмыстың ауқымына кірмейді. Сервер әдепкіде тек `127.0.0.1` адресін тыңдайды.
- Бұрыннан бар `sql/06_queries_lab8.sql` кеңейтілген `CinemaLabDB` схемасына арналған. Ол осы жеті кестелік `CinemaSchoolDB` орнату қадамдарына кірмейді. №9 суретіндегі кеңейтілген схема да осы айырмашылықпен құжатталған.

## Қорғауда көрсету реті

1. №9 диаграммасындағы үш деңгей мен DAL міндетін түсіндіріңіз.
2. `npm start`, `/api/health` және каталогты ашыңыз.
3. Postman коллекциясының GET -> POST -> GET by ID -> PUT -> GET -> DELETE -> GET 404 тізбегін көрсетіңіз.
4. Қате өрістерге 400, байланысқан фильмді жоюға 409 шығатынын көрсетіңіз.
5. `server/movies.js` ішіндегі `.input(...)`, `OUTPUT INSERTED.*` және `OUTPUT DELETED.movie_id` бөліктерін түсіндіріңіз.
6. Төмендегі толық есептің тоғыз бақылау сұрағына жауап беріңіз.
